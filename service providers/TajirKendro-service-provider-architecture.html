01 · The problem

Don't rebuild the same engine in every plugin.

TajirKendro is intended to grow into an ecosystem of specialized commerce tools. The infrastructure underneath those tools should not be duplicated dozens of times.

DUPLICATION

Same code, different plugin

Product Price, SKU, Stock, Category and Order tools can all need similar retrieval, AJAX, tables and validation.

DRIFT

Every copy evolves differently

When shared code is copied, bug fixes, security improvements and performance optimizations must be repeated.

COUPLING

Plugins become harder to connect

Direct dependencies between business plugins make the ecosystem increasingly difficult to maintain.

The answer is not one giant plugin. It is a small set of shared providers underneath many focused plugins.
02 · Architecture

Providers below. Business plugins above.

The service layer owns common infrastructure. Specialized plugins own domain-specific behavior.

03 · The five providers

A deliberately narrow foundation.

Only create a provider when the responsibility is broad, reusable and worth centralizing.

01

Core Manager

Foundation of the ecosystem.

  • Plugin/provider registration
  • Dependencies & compatibility
  • Capabilities
  • Shared ecosystem configuration
02

Data Manager

One gateway to platform data.

  • Retrieval & CRUD
  • Queries, filtering, pagination
  • Metadata & custom tables
  • Caching & normalization
03

Request Manager

One request lifecycle.

  • AJAX & REST
  • Parsing & sanitization
  • Nonce/security checks
  • Validation & responses
04

UI Manager

One reusable admin experience.

  • Tables & filters
  • Search & pagination
  • Forms & modals
  • Notices & components
05

Task & Event Manager

Work later; react cleanly.

  • Queues & background jobs
  • Scheduling & retries
  • Ecosystem events
  • Decoupled communication
DESIGN RULE

Five providers. No infrastructure sprawl.

If a capability naturally belongs inside one provider, do not create another plugin for it.

04 · How they work together

A request should travel through a predictable path.

01 · USER

Admin action

User searches, filters, edits or launches a bulk operation.

02 · REQUEST

Request Manager

Receives, validates and authorizes the request.

03 · DATA

Data Manager

Retrieves or modifies the required WooCommerce data.

04 · TASK / EVENT

Async ecosystem

Large work is queued; important changes can emit events.

Example · Bulk Price ManagerUser filters products → UI Manager renders the table → Request Manager handles AJAX → Data Manager retrieves products → Task Manager processes large updates → Event system broadcasts price changes.

06 · Architectural rules

Boundaries matter more than the number of plugins.

Providers provide infrastructure.

They should solve reusable technical problems, not understand product-pricing or inventory business rules.

Specialized plugins provide business functionality.

A Price Manager decides what a price should become. It should not decide how every product is retrieved.

Prefer composition over duplication.

Build specialized functionality by consuming providers rather than copying their internals.

Keep the provider count intentionally small.

New providers should be introduced only when a responsibility becomes a genuine architectural boundary.

Keep providers loosely coupled.

A provider should expose a stable contract so the implementation can evolve without forcing every plugin to change.

07 · Planning

Build the foundation before multiplying plugins.

PHASE 01

Core + Data

Establish the ecosystem lifecycle and a stable data-access contract. Migrate the current Bulk Price Manager to it.

PHASE 02

Request + UI

Centralize AJAX, validation and the reusable admin table/filter experience.

PHASE 03

Task + Event

Add safe background processing and decoupled communication for large operations and integrations.

PHASE 04

Specialized expansion

Build SKU, Stock, Category, Order, Shipping and Promotion tools on the shared foundation.

PHASE 05

Connection Manager

Turn the growing family into selectable bundles, suites and a complete TajirKendro ecosystem toolkit.

SUCCESS CRITERION

New plugins should feel cheap to build.

If every new plugin keeps recreating infrastructure, the provider architecture is not doing its job.
