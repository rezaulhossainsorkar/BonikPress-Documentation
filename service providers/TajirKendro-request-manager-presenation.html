Foundational concepts

Context and correlation are first-class

These concepts explain not just what a request is, but the circumstances around it and how multiple requests form a larger logical operation.

Request Context

The request's circumstances

Structured environmental and execution information accompanies the request throughout its lifecycle. It can describe source, actor, originating component, execution environment, current state, target and related request information.

sourceactorenvironmentoriginstatetarget
Request Correlation

The request's relationships

Correlation connects requests that belong to one logical operation, workflow, chain or coordinated activity. It can support parent/child, causal, chained, grouped and related relationships.

Design doctrine

Seven rules that keep the provider clean

01

Request ≠ transport

HTTP, AJAX, REST, hooks and callbacks are mechanisms. The TajirKendro Request is the ecosystem concept carried by them.

02

Request ≠ domain

Request Manager coordinates communication; the appropriate provider owns the requested domain operation.

03

Local stays local

Not every internal function call needs to become an ecosystem request.

04

Context is first-class

Processing needs structured knowledge of the circumstances surrounding a request.

05

Correlation is substantial

Related requests can form chains and coordinated logical operations.

06

Core stays authoritative

Request Manager uses Core knowledge without duplicating Core ownership.

07

Two diagnostic levels

Core observes the ecosystem; Request Manager observes requests.
