TajirKendroPress Architecture

One ecosystem. Many plugins. One clean admin experience.

TajirKendroPress can be built from small, independent plugins while presenting them to store owners as coherent products and modules.

The core idea

Separate the software from the experience.

A plugin can remain an independent WordPress package without needing to create its own top-level WordPress menu.

Admin registration

Plugins register capabilities, not top-level menus.

Instead of every plugin calling WordPress's top-level menu API, TajirKendroPress can provide a shared registration API.

Old approach

function bpm_add_admin_menu() {

    add_menu_page(
        'Bulk Price Manager',
        'Bulk Price Manager',
        'manage_options',
        'bulk-price-manager',
        'bpm_render_admin_page',
        'dashicons-money-alt',
        56
    );

}

TajirKendroPress approach

function bpm_register_admin_page() {

    TajirKendropress_register_admin_page(
        array(
            'product'   => 'bulk-product-edit',
            'section'   => 'pricing',
            'slug'      => 'bulk-price-manager',
            'title'     => 'Bulk Price Manager',
            'capability'=> 'manage_options',
            'callback'  => 'bpm_render_admin_page',
        )
    );

}
The TajirKendroPress Admin API would be responsible for translating these registrations into WordPress add_menu_page() and add_submenu_page() calls. The individual plugin does not need to own the top-level navigation.
The end goal

100 plugins underneath. A handful of products above.

Build the software as modular capabilities, compose those capabilities into large products, and let TajirKendroPress provide the unified experience. This keeps the code maintainable without making the WordPress admin overwhelming.
